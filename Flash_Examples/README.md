# Flash programming

To program a microcontroller's flash memory, you can use two methods depending on what chip you use. The H5 series lets you use STM32CubeIde's built in memory management tool (more about this in the folder for the H5), and the G4 series chips are inferior to the H5, so you'll need to modify the linker script (.ld files) by hand (more about this in the the folder for the G4).

Both the G4 and the H5 uses a dual bank system, but the size of the memory is different. The G4 has 512Kb of memory and uses a page-based system with 2Kb pages. The H5 has 2Mb os memory and uses a sector-based system with 8Kb sectors. With this math you can see that both chips have 256 pages or sectors, 128/memory bank. We usually want to write in the end of the memory because it's usually empty. A major difference between the two chips is the size of the data that you can write at once. The G4 can take a smaller 64-bit or 8-byte while the H5 can take a 128-bit or 16-byte chunk of data.

A micro controller's flash memory has limited erase/write cycles before they wear out, so be careful about where you put the erase and write functions. Make sure to avoid the loops. A microcontroller can usually handle between 10.000 to 100.000 erase/write cycles.
